# ASO tooling

Entry point: `scripts/aso/aso <cmd>`. Python venv and node deps are created on first use under `~/.local/share/shuttle-music-aso/` (`venv/`, `node/`). Credentials: `~/.config/simplecity/play-credentials.json` (never in the repo). Package: `com.simplecityapps.shuttle`.

- `aso listing pull` overwrites the title/short/full text files (never graphics) in `android/app/src/main/play/listings/<locale>/`, the gradle-play-publisher default dir, so there is one source of truth. The release path (`publishReleaseBundle`) uploads the bundle only, not listings.
- `aso listing push [--locale X]` diffs repo vs live and checks the 30/80/4000 limits; dry run unless `--apply` (edits.listings.update + commit; retries with `changesNotSentForReview` when Play asks). `--apply` is for fast per-locale text tests. A locale without `title.txt` is refused.
- `aso track` searches each English keyword (the lines above the first `[country/lang]` header) for US, GB (en, en-GB), AU (en, en-AU), CA, IN, and each `[country/lang]` section only in its own run (US/es, MX, BR, RU, FR, DE). It appends `date,country,lang,keyword,rank,hits,top3` to `ranks.csv` (blank rank = absent from the hits Play returned), and public stats for us plus 10 competitors to `apps.csv`. About 420 requests a day (54 English keywords x 7 English runs + 32 locale keywords + 11 app lookups) at 1 s each, so ~8 minutes. `ASO_LIMIT=2` runs only the first keywords of each run for a smoke test; `ASO_DATA_DIR` redirects output.
- `aso report [--days 7]` prints per-country top-10/top-30 counts and moved keywords vs N days ago.
- `aso bulk ls|get [--latest]` lists/downloads bulk reports (`stats/installs`, `stats/store_performance`) from the developer's GCS bucket, filtered to `_com.simplecityapps.shuttle_` so the podcasts app's files are excluded; exits 3 when the service account lacks access.
- `com.simplecity.music-aso-track.plist` + `install-launchd.sh` schedule `track` daily at 07:43, logging to `track.log`. Not installed by default; `install-launchd.sh` must run from the primary checkout (the plist hardcodes its path) and bakes in absolute node/python3 locations.
