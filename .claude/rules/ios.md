# iOS app and the Shared.framework umbrella

The iOS port (epic #581, plan `docs/architecture/ios-port.md`). `ios/` is a SwiftUI app generated by
XcodeGen from `ios/project.yml`; it links the static `Shared.framework` that the `:shared` KMP module
(`shared/`, repo root) builds. Structure and conventions follow Shuttle Podcasts
(`~/projects/simplecity-apps/podcasts/main/mobile`, its `.claude/rules/ios.md`).

## Commands

All from the repo root unless noted.

```bash
# 1. Link the framework (after EVERY Kotlin change; Xcode never rebuilds it)
ios/scripts/build-framework.sh                 # Debug, simulator
ios/scripts/build-framework.sh --device        # Debug, device (--all for both, --release for Release;
                                               # other args go to Gradle, e.g. -q)
# same as: ./gradlew :shared:linkDebugFrameworkIosSimulatorArm64

# 2. Regenerate the Xcode project (after editing project.yml or adding/removing Swift files)
cd ios && xcodegen generate

# 3. Build for the simulator
cd ios && xcodebuild build -project S2.xcodeproj -scheme S2 \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath build/DerivedData -quiet

# 4. Unit tests (swift-testing + ViewInspector); pick the simulator by UDID
cd ios && xcodebuild test -project S2.xcodeproj -scheme S2 \
  -destination 'id=<UDID>' -derivedDataPath build/DerivedData
```

`xcrun simctl list devices available` lists UDIDs. Avoid the `·lease N` clones; Podcasts sessions lease
them. The spike was verified on `iPhone 16` (iOS 18.5) and `iPad Pro 11-inch (M5)` (iOS 27.2) with
Xcode 27.2 beta.

## Layout

```
shared/                     # :shared: s2.kmp-library + SKIE, exports :android:domain and :android:presentation
  src/iosMain/.../IosAppGraph.kt   # the iOS graph (placeholder: in-memory songs until Metro, #583)
ios/
  project.yml               # source of truth; S2.xcodeproj is generated but committed (as in Podcasts)
  scripts/build-framework.sh
  S2/
    ContentView.swift       # measures the window -> LayoutTier; AppShell draws the container
    Navigation/             # AppTab, Navigator (selected tab + one path per tab), ShellContainer
    Theme/LayoutTier.swift  # compact / regular / wide, same vocabulary as Android
    Features/               # Home, Library, Search, Playback (mini player, Now Playing presentation)
    KMP/AppGraph.swift      # the Swift handle on IosAppGraph
  S2Tests/                  # ViewInspector + swift-testing
```

## Shell

Mirrors `docs/architecture/app-shell.md` with HIG choices: `compact` is a bottom `TabView`; `regular` and
`wide` use `TabView` with `.sidebarAdaptable` (iOS 18+) or a `NavigationSplitView` (iOS 17). Each tab
has its own `NavigationStack`, bound to a path on `Navigator`, which lives above the layout so a tier
change keeps the tab and the pushed screens. The mini player is a `safeAreaInset` on each stack's root
screen. Now Playing is a `fullScreenCover` on compact and a form sheet otherwise, presented from
`ContentView`.

## Swift ↔ Kotlin

- `import Shared`. Domain types keep their names (`Song`, `Album`) because `:android:domain` is
  `export`ed; a module that's only a dependency would appear as prefixed copies instead.
- A Kotlin `StateFlow<T>` arrives as `SkieSwiftStateFlow<T>` (`List<Song>` becomes `[Song]`). Observe it
  in SwiftUI with `Observing(flow) { value in ... }` (SKIE's `enableSwiftUIObservingPreview`), or read
  `.value` synchronously.
- For tests, split a screen into an `Observing` wrapper and a plain view that takes values (`LibraryView`
  / `SongList`). ViewInspector does render through `Observing` too: it starts from the StateFlow's value.

## Gotchas

- **Relink before building.** Xcode links whatever `Shared.framework` is on disk; a Kotlin change
  without `build-framework.sh` gives a stale binary or "has no member" errors.
- **Framework slices are chosen by SDK**, not configuration (`FRAMEWORK_SEARCH_PATHS[sdk=...]`); a
  device build needs `--device` first. There is no x86_64 simulator slice, so x86_64 is excluded.
- **The test bundle does not link Shared.** It only has the search path for `import Shared`; the Kotlin
  code resolves from the host app through `BUNDLE_LOADER`. Linking the static framework into the tests
  as well would load a second Kotlin runtime.
- **ViewInspector is pinned to 0.10.3.** Later releases declare `.visionOS(.v2)` under a 5.9 tools
  version, which Xcode 27's SwiftPM rejects, and package resolution fails.
- **Kotlin/Native wants a framework bundle id**; `shared/build.gradle.kts` sets
  `binaryOption("bundleId", ...)` to silence the link warning.
- `:shared` is in `ModuleLayers` as a composition root (it aggregates the shared modules for iOS as
  `:android:app` does for Android); a new exported module needs no layer change.
- The bundle id `com.simplecityapps.shuttle.dev` is a placeholder until the App Store Connect app exists.
