# iOS app and the Shared.framework umbrella

The iOS port (epic #581, plan `docs/architecture/ios-port.md`). `ios/` is a SwiftUI app generated by
XcodeGen from `ios/project.yml`; it links the static `Shared.framework` that the `:shared` KMP module
(`shared/`, repo root) builds. Structure follows Shuttle Podcasts (`~/projects/simplecity-apps/podcasts/main/mobile`,
its `.claude/rules/ios.md`). Use `support/scripts/asc`, not Chrome, for App Store Connect (`ios/DEPLOY.md`).
Audio session, Now Playing and engine notes: `ios-playback.md`; device runs, the POC and Maestro: `ios-device.md`.

## Commands

From the repo root.

```bash
# 1. Link the framework (after EVERY Kotlin change; Xcode never rebuilds it)
ios/scripts/build-framework.sh                 # Debug, simulator; --device, --all, --release; other args go to Gradle

# 2. Regenerate the Xcode project (after editing project.yml or adding/removing Swift files)
cd ios && xcodegen generate

# Strings: after adding a StringKey/PluralKey (or a plural in IOS_PLURALS) or changing its Android text/translation,
# regenerate ios/S2/<locale>.lproj/Localizable.strings + .stringsdict (--check exits 1 if stale or if project.yml's
# CFBundleLocalizations disagrees). Swift plurals: pluralized(n, .song) / localizedPlural(key, n, args...).
# Test: python3 -m unittest discover -s ios/scripts
ios/scripts/generate-strings.py

# 3. Build for the simulator (build-for-testing into ios/build/DerivedData; skipped when nothing under ios/ or
#    shared/ changed). Workers call this, never raw xcodebuild. --force rebuilds and relinks regardless
ios/scripts/build-app.sh

# 4. Tests: the S2 scheme (swift-testing + ViewInspector) on this session's leased simulator, else an iPhone on a
#    released runtime. S2_SIMULATOR_UDID=<udid> picks one; extra args go to xcodebuild (-only-testing:S2Tests/AppShellTests)
ios/scripts/test.sh
ios/scripts/test.sh --package                  # swift test in ios/Playback on the Mac (extra args: --filter ...)
```

Cold-start timing: `ios/scripts/startup-bench.sh --sim -n 5` (leases a sim, streams the `Startup` OSLog category, prints
median/min/max per milestone; `--help` for `--device`, `--append` and launch args; `docs/performance/ios-startup.md`).

`test.sh` builds through `build-app.sh` then runs `test-without-building`. Release is for archive/deploy only
(`ios/archive-and-upload.sh`). The xcodebuild calls share one SPM clone cache (`~/Library/Caches/s2-spm`) across
worktrees, and Xcode compilation caching shares one CAS (`~/Library/Caches/s2-xcode-cas`, `ios/scripts/xcode-cache.sh`;
`S2_XCODE_CAS=off` disables; Debug builds only, capped at 10 GB, prefix-mapped so entries carry no worktree paths): a
cold DerivedData build with a warm CAS took 79s against 106s uncached (-26%, Xcode 27.2), and two concurrent builds on
one CAS both succeed. Deleting `~/Library/Caches/s2-xcode-cas` is always safe; the next build refills it. Don't set the
S2Tests scheme `parallelizable`: Swift Testing already runs in parallel in-process, and cloning made the suite slower
and flaky.

`test.sh`, `run-sim-server.sh` and `maestro-sim.sh` lease their simulator from the shared ios-sim pool
(`~/.claude/scripts/ios-sim/device.sh`); `$S2_SIM_HOLDER` leases as a different holder for parallel workers.
`S2_SIM_PROFILE=ios26` (via `ios/scripts/lease-sim.sh`) leases from the `S2 iPhone iOS 26` pool (runtime 26.5; needed for
tab-bar-minimise and bottom-accessory behaviour) under a `-ios26` holder; release with
`CLAUDE_CODE_SESSION_ID="$(ios/scripts/lease-sim.sh --holder)" ~/.claude/scripts/ios-sim/sim-lease.sh release` (land.sh does).
Default pool is iPhone 16 on iOS 18.5. On an iPhone with the iOS 27.2 beta `AppShellTests`' two TabView lookups fail, so
`test.sh`'s no-pool fallback skips beta runtimes unless nothing else has an iPhone (#601). ViewInspector can't see into
iOS 26's `safeAreaBar`, so a pinned bar is its own property for tests (`LibraryRootContent.categoryRail`,
`SearchContentView.typeChips`), and its `findAll` skips what's inside an iOS 26 `LibraryRowLink`: use
`findAllBreadthFirst` (`S2Tests`).

**Verification split:** a worker's brief only needs the Swift package build/tests for the files it touched, and gives up
on a simulator lease after ~5 minutes. `land.sh` (when the picked commits touch `ios/`, `shared/`, or
`android/domain|presentation|core`) rebuilds the framework, builds the app and runs `test.sh -only-testing:` for the
`S2Tests` classes mapped from the changed files (`ios/S2Tests/Foo*Tests.swift` runs itself; `ios/S2/**/Foo.swift` runs
`S2Tests/Foo*Tests`; `land.sh --print-ios-tests <files>` dry-checks); no mapped class means build only, no lease. The
whole scheme runs in `full-verify.sh`. Both lease as their own holder (`S2_SIM_HOLDER=land` / `full-verify`).

## Layout

```
shared/                     # :shared: s2.kmp-library + SKIE, exports :android:domain and :android:presentation
  src/iosMain/.../IosAppGraph.kt   # the Metro graph; Swift builds it with IosAppGraphKt.createIosAppGraph(audioPlayer:)
  src/iosMain/.../di/              # IosPersistenceModule, IosNetworkingModule, IosPlaybackModule, IosPlatformModule,
                                   # IosEntitlementModule (StoreKit-fed Pro gate, #609)
  src/iosMain/.../platform/        # Apple-backed bindings: NWPathMonitor, NSBundle text/strings, MediaSources
ios/
  project.yml               # source of truth; S2.xcodeproj is generated but committed (as in Podcasts)
  S2/
    Settings.bundle/        # Acknowledgements: FFmpeg's LGPL notice, relink note, LGPL text, shuttle-playback's
    Info.plist              # generated by XcodeGen from project.yml `info:`; don't edit
    ContentView.swift       # measures the window -> LayoutTier; AppShell draws the container
    Navigation/             # AppTab, Navigator (selected tab + one path per tab), ShellContainer
    Theme/LayoutTier.swift  # compact / regular / wide, same vocabulary as Android
    Features/               # Home, Library, Search, Playback (mini player, Now Playing presentation)
    KMP/                    # AppGraph (initialize() at launch), ViewModelCache, CombineFlowBridge, ViewModelGroup, ConsumeEvents
    Platform/Audio/         # AudioSessionController, NowPlayingController, EngineAudioPlayer, PlaybackSystemCoordinator
    Platform/SystemIntents/ # App Intents for Siri/Shortcuts/Spotlight (#758): AppIntentPerformer, IntentPerformers,
                            # NowPlayingWidgetPublisher (writes the widgets' state)
  SystemSurfaces/           # compiled into the app AND S2Widgets: playback App Intents, NowPlayingStore (App Group
                            # snapshot). No `import Shared` here: the extension doesn't link the framework
  S2Widgets/                # WidgetKit extension: Now Playing widgets, the iOS 18 play/pause control
  Playback/                 # the S2Playback package: gapless engine (see its README); no AVAudioSession.
                            # A local package dependency of the S2 target only (project.yml `packages:`)
  S2Tests/                  # ViewInspector + swift-testing
```

## Shell

Mirrors `docs/architecture/app-shell.md`. `compact` is a bottom `TabView`; `regular`/`wide` use `TabView` with
`.sidebarAdaptable` (iOS 18+) or a `NavigationSplitView` (iOS 17). Each tab has its own `NavigationStack` bound to a
path on `Navigator`, which lives above the layout so a tier change keeps the tab and pushed screens. The mini player is
a `safeAreaInset` (`.miniPlayerInset`) on each stack's root and every pushed screen (`routeDestinations`, which must be
applied inside the stack: outside it SwiftUI ignores it and links never push) (#593). Now Playing is a `fullScreenCover`
on compact and a form sheet otherwise, presented from `ContentView`.

## Swift ↔ Kotlin

- `import Shared`. Domain types keep their names (`Song`, `Album`) because `:android:domain` is `export`ed; a module
  that's only a dependency would appear as prefixed copies instead.
- A Kotlin `StateFlow<T>` arrives as `SkieSwiftStateFlow<T>`. Observe it with `Observing(flow) { value in ... }`
  or read `.value`. For tests, split a screen into an `Observing` wrapper and a plain view that takes values
  (`LibraryView` / `SongList`); ViewInspector renders through `Observing` too.
- **Screen view models come from `ViewModelCache.shared`**, keyed by screen and argument (`"album:42"`), never stored
  straight off the graph: a SwiftUI view struct is re-initialised on every parent body, so a fresh view model per init
  restarts every flow `Observing` is keyed on. Clear entries when their route leaves the path (`remove`/`retainOnly`).
  Every shared ViewModel is a `ClearableViewModel` through `clearFromSwift()` (`shared/.../di/ViewModelClearing.kt`).
- **Swift-fed flows** (prefs, scene phase): `publisher.toKotlinFlow { ... }` (`CombineFlowBridge.swift`) returns
  `WritableFlow<T>` (`shared/.../di/WritableFlow.kt`, replay 1), which holds the Combine subscription. `T` must be an
  object type (`NSString`, `KotlinBoolean`, a Kotlin class). The flow is released by the Kotlin GC, not when Swift drops it.

## Gotchas

- **FFmpeg comes from shuttle-playback** (#957). `Playback/Package.swift` pins the package `exact:`; decode is its
  `PlaybackDecode`, and `S2Tags` links its `FFmpeg` product (one static xcframework, one FFmpeg in the app binary).
  Never add a second FFmpeg or shim around a gap in the package's API in the app: fix it upstream. Bumping the pin
  means bumping the tag in `SettingsContent.ffmpegSourceURL` and the Acknowledgements pane too.
- **Relink before building.** Xcode links whatever `Shared.framework` is on disk; a Kotlin change without
  `build-framework.sh` gives a stale binary or "has no member" errors.
- **Framework slices are chosen by SDK**, not configuration (`FRAMEWORK_SEARCH_PATHS[sdk=...]`); a device build needs
  `--device` first. There is no x86_64 simulator slice.
- **The test bundle does not link Shared.** It only has the search path for `import Shared`; Kotlin resolves from the
  host app through `BUNDLE_LOADER`. Linking the static framework into the tests too would load a second Kotlin runtime.
- **Kotlin/Native wants a framework bundle id**; `shared/build.gradle.kts` sets `binaryOption("bundleId", ...)`.
- `:shared` is in `ModuleLayers` as a composition root (like `:android:app`); a new exported module needs no layer change.
- The bundle id `com.simplecityapps.shuttle.dev` is a placeholder until the App Store Connect app exists.
- **Info.plist is merged.** `GENERATE_INFOPLIST_FILE` stays on and Xcode merges `S2/Info.plist` into it, but the file's
  keys win, so its versions point at `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)`. Add keys under project.yml
  `info: properties:`, not in the plist.
- SourceKit shows "No such module 'Testing'" and "AVAudioSession is unavailable in macOS" for these files; xcodebuild is
  the truth.
- **S2Tests never builds a real engine.** Tests make their own `IosAppGraphKt.createIosAppGraph(audioPlayer:
  EngineAudioPlayer(engine: FakeAudioEngine()))` and queue `TestSongs.demo`; `AppGraph.shared` is the host app's, with a
  real `MusicPlaybackController`. Kotlin work arrives on the main queue after the call returns, so await it with
  `waitUntil { ... }` (`FakeAudioEngine.swift`).
